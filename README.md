# HappyLulu

<img src="Resources/HappyLuluIcon.png" width="160" alt="HappyLulu 웃는 시계 아이콘">

**우리의 하루를 더 즐겁게.** 룰루랩 동료들을 위한 작은 macOS 메뉴바 도구입니다. 허용 시간에 처음 감지한 맥 잠금 해제 시각을 출근으로 저장하고, 퇴근까지 남은 시간을 표시합니다.

## 사용

1. `~/Applications/HappyLulu.app`을 실행합니다.
2. 메뉴바의 웃는 시계 아이콘과 `출근 대기`를 클릭합니다.
3. 이미 출근했다면 **출근 시각 입력**으로 오늘 시각과 근무 유형을 입력합니다. 앱 실행 시각을 출근으로 추정하지 않습니다.
4. 앱이 실행 중일 때 일반 근무·오후 반차는 08:00~10:00, 오전 반차는 13:00~15:00 사이의 첫 잠금 해제를 자동 기록합니다. 종료 시각의 분 전체를 허용합니다.
5. **설정 → 근무**에서 근무·휴게시간을 조정합니다. 기본은 8시간 + 1시간입니다.

## 다우오피스–Google 캘린더 동기화

**설정 → 캘린더 → HappyLulu Calendar 열기** 또는 **설정 → 캘린더 → HappyLulu Calendar 열기**에서 별도 캘린더 창을 엽니다. Finder에서 앱을 재실행하면 설정 창을 엽니다. 계정 인증은 HappyLulu 안에서 받지 않고 macOS **시스템 설정 → 인터넷 계정**을 사용합니다.

1. 캘린더 창에서 **인터넷 계정 열기**를 누릅니다.
2. Google 계정을 추가합니다. macOS가 Google 웹 로그인을 열고 인증정보를 관리합니다.
3. **기타 계정 → CalDAV 계정**에서 서버 `lululab.daouoffice.com`, 다우오피스 로그인 이메일과 비밀번호를 입력합니다. 공식 CalDAV 인증은 웹 OAuth가 아닌 계정 비밀번호 방식이며 macOS가 보관합니다.
4. **캘린더 연결 허용**을 누르고 macOS 권한 창에서 캘린더 접근을 허용합니다. 앱 화면을 열기만 해서는 권한을 요청하지 않습니다.
5. 인터넷 계정의 CalDAV 캘린더 목록에서 서로 다른 다우오피스·Google 계정의 테스트 캘린더를 하나씩 고릅니다. 계정 이름과 연결 여부 확인에 체크한 뒤 **첫 동기화 미리보기**를 확인합니다. 공개 EventKit API로 서버 주소를 확인할 수 없어 이 확인이 필요합니다.
6. 추가 방향, 중복 의심, 충돌과 지원 제외 건수를 확인한 뒤 **양방향 동기화 시작**을 누릅니다.

정상 상태에서는 한 주기가 끝난 뒤 약 1시간 후 다시 실행합니다. 앱 시작, 절전 복귀, 네트워크 복구 때 예정 시각이 지났으면 한 번 실행합니다. 인증이 만료되면 반복 로그인을 멈추고 재연결을 안내합니다.

처음 동기화를 시작할 때는 미리보기와 현재의 양쪽 일정 내용·버전·연결 상태를 다시 대조합니다. 내용이 달라졌거나 예전 버전의 미리보기만 남아 있으면 일정을 쓰지 않고 새 미리보기를 요구합니다. 첫 저장 결과가 불확실하면 기존 journal을 먼저 확인하고, 확인 전에는 새로 발견한 일정의 복사를 보류합니다. 저장을 시도하지 않은 것으로 확인된 첫 작업은 새 미리보기와 다시 대조합니다.

첫 버전은 제목, 시작·종료 시각, 종일 여부, 시간대, 설명과 장소의 추가·수정을 처리합니다. 반복 일정과 그 수정된 회차, 초대·참석자, 알림, 기존 URL과 서버 식별자를 확인할 수 없는 일정은 자동 쓰기에서 보류합니다. 회의실·결재·첨부 등 특수 속성을 macOS가 드러내지 않으면 정확히 판별할 수 없으므로 일반 개인 캘린더의 일정만 선택하세요. 다우오피스 제한에 따라 제목에 `/`가 들어간 일정도 보류합니다.

양쪽에서 같은 일정을 다르게 수정했다면 자동 덮어쓰기를 멈춥니다. 화면에서 양쪽 제목을 확인하고 적용할 쪽을 직접 고를 수 있습니다. 적용 직전에 로컬 캘린더의 최신 버전을 다시 확인합니다. EventKit 조회 누락은 서버의 삭제 증거가 아니므로 **현재 버전은 일정 삭제를 상대 캘린더에 자동 반영하지 않습니다.** 삭제되거나 조회할 수 없는 연결 일정은 보류합니다.

복사한 일정에는 중복 복사를 막는 HappyLulu URL 표시를 저장합니다. 저장 직후 앱이 중단되면 이 표시로 기존 복사본을 찾습니다. 이전 저장 결과를 확인할 수 없으면 자동으로 새 복사본을 만들지 않고 보류합니다. 서버 식별자를 연결하기 전에 URL 표시가 사라지면, 복사본을 새 원본으로 오인하지 않도록 그쪽의 새 일정 가져오기도 보류합니다. 동기화를 시작한 캘린더 쌍은 연결 기록을 보존하기 위해 선택을 고정합니다.

- 동기화 상태: `~/Library/Application Support/HappyLulu/CalendarSync/sync.sqlite`
- 계정 인증정보: macOS 인터넷 계정이 관리하며 HappyLulu 저장소에는 넣지 않습니다.
- 계정 해제: macOS 인터넷 계정에서 수행합니다. HappyLulu 일시 중지는 이미 복사된 일정을 지우지 않습니다.
- 새로 가져올 범위: 과거 30일~미래 365일. 서버 식별자가 확인된 연결 일정은 범위 밖에서도 조회합니다. 서버 식별자가 아직 없는 새 복사본은 다음 조회에서 식별자를 연결하며, 그 전에 범위 밖으로 옮기거나 조회할 수 없으면 보류합니다.

회사 보안 정책이 macOS 인터넷 계정의 Google 또는 CalDAV 연결을 허용해야 동작합니다. 실제 일정에 적용하기 전 양쪽에 별도 테스트 캘린더를 만들어 미리보기와 왕복 시험을 먼저 진행하세요. macOS 캘린더가 서버와 통신하므로 HappyLulu의 성공은 로컬 캘린더 저장 성공을 뜻하며, 실제 웹 캘린더 반영도 별도로 확인해야 합니다.

출근 08:47, 근무 8시간, 휴게 1시간이면 퇴근 예정은 17:47입니다. 남은 시간은 실제 시각 차이로 계산하며 약 15초마다 갱신합니다. 절전·점심 잠금 동안에도 시간은 흘러갑니다. 퇴근 시각 이후에는 `퇴근 가능`으로 표시합니다.

**반차:** 오전 반차는 13:00~15:00에 출근하면 출근 4시간 뒤 퇴근합니다. 오후 반차는 08:00~10:00에 출근해 휴게시간 없이 4시간 근무한 뒤 바로 퇴근합니다. 반차에는 설정한 근무·휴게시간이나 마지막 금요일 2시간 단축을 추가 적용하지 않습니다. 일반 근무의 마지막 금요일 규칙은 그대로 유지됩니다.

13:00~15:00의 잠금 해제나 수동 시각은 오전 반차로 자동 판단합니다. 오후 반차는 **출근 시각 입력 → 근무 유형**에서 직접 지정할 수 있습니다. **캘린더 반차 자동 인식**을 켜고 macOS 캘린더 접근을 허용하면, 접근 가능한 일정 제목의 `오전 반차`·`오후 반차`도 자동 판단에 사용합니다. 모호한 `반차` 제목이나 서로 다른 유형의 일정이 함께 있으면 추측하지 않고 출근 시각으로 판단합니다. 수동으로 고른 일반 근무·오전 반차·오후 반차는 캘린더보다 우선하며, 오늘 이미 기록한 출근도 같은 시각으로 유형만 바꿔 저장할 수 있습니다. 새 캘린더 결과가 기록된 출근 시각과 맞지 않으면 이전에 자동 인식한 반차를 철회하고 시각으로 다시 판단합니다. 캘린더 읽기 자체가 실패했을 때에만 마지막으로 확인한 유형을 유지합니다. 반차 인식은 캘린더 일정을 수정하지 않습니다.

**매달 마지막 금요일에는 자동으로 2시간 일찍 퇴근합니다.** 같은 설정에서 09:00에 출근하면 평소 18:00, 마지막 금요일에는 16:00입니다. 출근을 기록한 시간대의 양력 날짜로 판별하며, 팝업에 `마지막 금요일 · 2시간 조기 퇴근`을 표시합니다. 메뉴바 남은 시간과 진행률도 단축된 퇴근 예정 시각을 따릅니다. 출근 전에는 현재 맥 시간대로 오늘의 적용 여부를 안내합니다.

일반 근무의 단축일 계산은 `출근 + 근무 + 휴게 − 2시간`입니다. 설정한 근무·휴게 합계가 2시간 이하면 퇴근 예정은 출근 시각으로 제한합니다. 네 번째 또는 다섯 번째 금요일 중 해당 월의 마지막 금요일에만 적용하며, 공휴일 대체나 다른 날짜로의 이월은 하지 않습니다.

화면은 기존과 같이 맥의 현재 로컬 날짜에 해당하는 출근 기록을 보여줍니다. 시간대 변경으로 맥의 날짜가 달라지면 해당 날짜의 기록으로 전환하며, 선택된 기록의 조기 퇴근 여부는 출근 당시 시간대를 따릅니다.

출근 시각은 하루에 한 번만 자동 기록하고 이후 잠금 해제로 덮어쓰지 않습니다. 직접 수정한 기록도 유지됩니다. 설정 변경은 오늘 퇴근 예정에 즉시 반영됩니다. **오늘 쉬는 날**은 확인 후 오늘 기록을 삭제하고 오늘 자동 기록을 멈춥니다. 출근 시각을 직접 입력하면 다시 시작합니다. 최근 기록은 7건을 화면에 표시하고 저장된 과거 기록은 유지합니다.

## 기록과 자동 실행

- 기록 파일: `~/Library/Application Support/AfterSix/state.json`
- 이전 AfterSix 기록과 설정을 그대로 사용합니다. 이름 변경으로 기록을 새로 만들거나 초기화하지 않습니다.
- 출퇴근 기록은 네트워크·서버·계정 없이 로컬에만 저장합니다. 캘린더 기능은 사용자가 선택한 macOS 시스템 캘린더만 읽고 씁니다. 키보드 입력이나 화면 내용은 수집하지 않습니다.
- 첫 실행에 `SMAppService.mainApp`으로 로그인 자동 실행을 등록합니다. 시스템 승인이 필요하면 앱에 안내합니다. 이후 사용자가 끈 설정을 자동으로 다시 켜지 않습니다.
- 저장 파일은 원자적으로 교체하고 사용자 읽기·쓰기 권한만 설정합니다. 손상되거나 지원하지 않는 버전이면 원본을 덮어쓰지 않고 오류를 표시합니다.
- 메뉴의 **종료**는 감지를 중단합니다. 자동 실행 등록은 유지됩니다. 자동 실행을 끄려면 설정 토글을 끕니다.

## 정확도와 범위

- 감지는 macOS의 `com.apple.screenIsUnlocked` 분산 알림을 사용합니다. Apple이 문서화한 공개 계약이 아니므로 macOS 업데이트 이후 실제 잠금/해제 검증이 필요합니다. 개인용 로컬 배포 범위입니다.
- 절전 해제, 화면 켜짐, 사용자 세션 전환만으로 출근을 기록하지 않습니다.
- 앱을 설치하기 전이나 앱이 종료된 동안의 과거 잠금 해제는 복원하지 않습니다.
- 재부팅 직후 첫 로그인과 기존 세션의 잠금 해제는 다릅니다. 첫 로그인에서 해당 알림이 발생하지 않으면 수동 입력이 필요합니다.
- 집에서 맥을 먼저 해제하면 그 시각이 기록됩니다. 회사 위치·Wi-Fi 판별은 포함하지 않습니다.
- 맥의 현재 로컬 달력 날짜와 허용된 출근 시간을 기준으로 기록합니다. 자정에 오늘 화면이 새 날짜로 전환됩니다. 야간 교대근무·기기 간 동기화·급여용 근태 증빙은 범위에 포함하지 않습니다.
- 허용 시간 전에 해제한 채 계속 사용하는 경우 자동 출근을 만들지 않습니다. 필요하면 직접 입력합니다.
- 최근 기록의 시각은 기록 당시 시간대를 사용합니다.

## 앱 업데이트

1.5.1에는 새 버전 확인 UI가 있습니다. **현재 서명된 업데이트 목록 게시가 보류되어 앱 안의 업데이트 서비스는 아직 활성화되지 않았습니다.** 활성화 후에는 새 버전을 자동으로 확인하고 안내합니다. **설정 → 업데이트 → 지금 업데이트 확인**으로 직접 확인할 수도 있습니다. 사용자가 업데이트를 선택한 뒤 다운로드·설치·재실행합니다. 동의 없이 설치하지 않으며 자동 확인은 끌 수 있습니다.

이번 1.5.1은 다운로드 사이트에서 수동으로 교체합니다. 이후 자동 업데이트를 활성화한 앱이 배포되면 그 앱으로도 한 번 수동 교체해야 하며, 그다음 버전부터 앱 안에서 업데이트할 수 있습니다. 출근 기록과 캘린더 연결은 앱 밖의 기존 저장 경로를 유지합니다. 자세한 배포·서명 절차는 [UPDATES.md](UPDATES.md)를 확인하세요.

```sh
bash scripts/package-release.sh
```

Universal 앱과 DMG·ZIP, 릴리즈 노트, SHA-256 파일은 `dist/releases/<버전>-build<빌드>/`에 생성합니다. Apple Silicon과 Intel을 각각 빌드해 결합하고 ad-hoc 서명을 검증합니다. 이미 있는 버전의 배포 폴더는 덮어쓰지 않습니다. 배포 전에 ZIP·DMG 안의 앱이 원본과 일치하는지 확인해야 합니다. 실제 Intel 실행과 다운로드 후 첫 실행은 빌드·서명 검사와 별도입니다.

앱 bundle·배포 산출물은 Git에 넣지 않습니다. 일반 사용자는 소스 빌드 없이 DMG 또는 ZIP을 받아 설치하며, 로그인 계정은 본인의 macOS에서 연결합니다.

## 개발

macOS 13 이상, Swift 6 이상. 앱 업데이트에 Sparkle 패키지를 사용합니다. Xcode 전체 앱 없이 Command Line Tools로 앱을 빌드할 수 있습니다.

```sh
bash scripts/build-app.sh
swift run --build-system native AfterSixChecks
swift run --build-system native CalendarSyncChecks
swift run --build-system native CalendarSyncServiceChecks
```

산출물은 `dist/HappyLulu.app`이며 로컬 ad-hoc 서명을 합니다. App Store 배포나 Developer ID 공증은 수행하지 않습니다.

소스에서 빌드한 앱은 Finder에서 `dist/HappyLulu.app`을 `~/Applications/`로 복사한 뒤 실행합니다.
이미 실행 중인 앱을 교체할 때는 메뉴의 **종료**로 먼저 닫습니다. 위의 사용 절차는 설치 후 기준입니다.

호환성을 위해 내부 타깃 `AfterSix`/`AfterSixCore`, 저장 경로와 번들 ID `local.chanyoung.AfterSix`는 유지합니다. 사용자에게 보이는 이름과 실행 파일은 HappyLulu입니다. 아이콘 원본과 제작 정보는 [BRANDING.md](BRANDING.md)에 있습니다.

검사는 XCTest 설치 없이 실행하는 독립 시나리오입니다. 현재 Command Line Tools의 새 빌드 엔진이 Xcode 프레임워크를 참조하므로 기존 native 빌드 엔진을 명시합니다. 이후 Swift 버전에서 해당 옵션이 제거되면 빌드 스크립트를 갱신해야 합니다.

설치된 앱의 읽기 전용 상태 확인:

```sh
~/Applications/HappyLulu.app/Contents/MacOS/HappyLulu --status
```

## 실제 맥 확인

앱을 실행한 상태에서 사용자가 직접 `Control + Command + Q`로 잠갔다가 해제합니다. 팝업 아래의 **최근 잠금 해제 감지**가 갱신되는지 확인합니다. 허용된 출근 구간이고 오늘 기록이 비어 있다면 출근 시각도 생성되어야 합니다. 두 번째 해제는 최초 출근 시각을 유지해야 합니다. 이 검사는 합성 알림이나 단위 검사로 대체할 수 없습니다.

로그인 자동 실행은 등록 상태 확인과 실제 로그아웃/로그인 후 실행 확인을 구분합니다.
